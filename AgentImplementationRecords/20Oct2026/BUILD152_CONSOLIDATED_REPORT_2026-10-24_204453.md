## 8. Findings the redo surfaced
1. **GST arithmetic differs from Zoho by one paisa.** Live read-only comparison of the five sandbox Sales Orders: four Rs 195.00 orders show Zoho 165.26 / 14.87 / 14.87 against EffyKlean 165.25 / 14.88 / 14.87; the Rs 11.80 order is identical. Totals always agree (EffyKlean refuses a Zoho order whose total differs); only the split differs. Cause: EffyKlean extracts the whole tax once (195 x 18/118 = 29.7458, rounded to 29.75, odd paisa to SGST) while Zoho rounds each component and takes the taxable value as the remainder. One amount is not enough to infer Zoho's general rule, and the rule is HU+DI-settled, so it was not changed. For the accountant.
2. **The token cannot read** purchase orders, adjustments, transfers, invoices or packages (401), and lacks `contacts.UPDATE`.
3. **The test organisation has one location and no bins**; item reads with and without a location id are identical.
4. **The first-pass product list makes 15 inline Zoho availability calls per page** (about 2.6 s estimated, not measured end to end); an optional cache exists, default off.
5. **The old order page said Zoho invoicing was "not integrated"** and the cancel page named Razorpay; both corrected.
